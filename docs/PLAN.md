작성일: 2026-09-25 · 상태: **v1.2 — 릴리즈 1(카메라) ✅ · 릴리즈 2(효과) ✅ (09-26) · 릴리즈 3(쇼츠) 다음** · 결정 이력 §10 · 협업 방식 §11

## 1. 목표

**나 혼자 쓰는 iPhone 앱 하나로** 다음 두 가지를 끝낸다. 외부 앱(편집 앱, Mac 스크립트, 서드파티 스토어)에 기대지 않는다.

1. **사진 보정 (주 기능)** — 카메라 라이브 화면과 앨범 사진 모두. 자동 보정 + 여행용 프리셋 + 인물 보정(피부·얼굴 윤곽). **결과는 항상 내 사진 보관함에 저장되고, 촬영 위치·날짜·카메라 정보(EXIF/GPS)는 그대로 유지**된다.
2. **여행 쇼츠 (보조 기능)** — 영상 규격(9:16 등)을 고르면 그에 맞춰 촬영을 돕고, 찍은 클립을 음악과 함께 붙여 내보낸다. 음악은 YouTube 링크에서 앱이 직접 가져온다.

복잡한 기능은 넣지 않는다. 화면은 4개, 설정은 한 페이지.

## 3. 기능 ① 사진 보정

### 3.1 진입점
- **앱을 켜면 바로 카메라(라이브 화면)**다. 다른 탭은 필요할 때만 간다.
- **라이브**: 프리뷰에 선택한 프리셋(+ 인물 모드가 켜져 있으면 인물 보정)을 **실시간 적용해 보면서 촬영**한다(저해상도, Metal, 30fps). 셔터를 누르면 Apple ISP 처리 원본을 받아 **같은 설정을 풀해상도로 후처리** → 원본과 함께 사진 앱에 저장(비파괴). 프리뷰와 저장본은 같은 파이프라인이므로 보이는 대로 저장되며, 저장본이 해상도만 더 높다. 렌즈: 후면 0.5×/1×/2× 버튼(가상 트리플 카메라 자동 전환) + 전면 전환(프리뷰만 미러).
- **앨범**: 사진 선택(여러 장 가능) → 자동 보정 또는 프리셋 → 전/후 비교 → 저장. 일괄 처리.

### 3.2 보정 파이프라인 (순서 고정, 각 단계 강도 0~100)
| 단계 | 내용 | 구현 |
|---|---|---|
| 1 자동 | Apple 자동 개선(적목·얼굴 밸런스·색·톤) | `CIImage.autoAdjustmentFilters()` |
| 2 톤·색 | 노출, 대비, 하이라이트/섀도우, 화이트밸런스, 생동감 | Core Image 내장 필터 |
| 3 인물 | §3.3 | Vision + Metal |
| 4 선명도 | 언샤프 마스크 + 로컬 대비. 피부 마스크 바깥에만 | `CIUnsharpMask` + Metal 커널 |
| 5 저조도 | Zero-DCE++ (야경 프리셋에서만 켜짐) | Core ML |
| 6 색감 룩 | 3D LUT (.cube) | `CIColorCubeWithColorSpace` |
| 7 마무리 | 수평 자동 보정, 비네팅 | Vision 수평선 검출, `CIVignetteEffect` |

**프리셋**: 위 파라미터 묶음. 기본 6종(맑은 하늘, 골든아워, 야경, 음식, 실내, 흑백) + 직접 저장. 프리셋 하나가 라이브·앨범·영상에 동일하게 적용된다.

### 3.3 인물 보정 — "인물 모드" 토글
촬영 화면 상단의 **인물 모드 스위치**로 켜고 끈다(앨범 보정 화면에도 같은 스위치).
- **켜면**: Vision 얼굴 검출 → 얼굴별 피부·윤곽·눈·치아 보정이 프리셋 위에 적용. 얼굴이 없으면 아무 일도 하지 않는다.
- **끄면**: 얼굴이 있어도 일반 보정만. 풍경·음식 촬영 시 불필요한 얼굴 검출 비용도 없앤다.
- 얼굴이 검출되면 화면에 작은 얼굴 표시를 띄워 "지금 인물 보정 중"임을 알린다. 마지막 상태를 기억한다.
- 기본값은 낮게(피부 30, 윤곽 20).

| 기능 | 방법 |
|---|---|
| 피부 부드럽게 | 얼굴 랜드마크 + 피부색 범위로 피부 마스크 → 마스크 안에만 하이패스 주파수 분리(질감 유지, 잡티·요철만 완화). 라이브에서는 양방향 필터로 가볍게 |
| 얼굴 날렵하게 | 턱선·광대 랜드마크 기준 메시 워프(Metal). 좌우 대칭, 배경 왜곡 감쇠 |
| 눈 키우기, 치아 미백 | 같은 워프·마스크 방식. 옵션 |
| 여러 명 | 얼굴별 독립 처리, 최대 5명. 모두 같은 강도 |
| 강도 3단계 칩 | 자연/보통/강함 한 번에 선택(피부·윤곽·눈·치아 값 묶음). 촬영·앨범 화면 모두. 슬라이더는 세부 조정용 |
| 배경 흐림 | Vision 인물 분리(`VNGeneratePersonSegmentationRequest`)로 배경만 흐림. 강도 0~100. **저장·앨범에서만**(라이브 미적용), 사람이 없으면 무동작 |

**인물 모드 UX**: 촬영 화면 인물 버튼은 셔터 옆(켜지면 노란 얼굴 아이콘), 라이브 얼굴 마커(작은 모서리 표시, 1초 후 사라짐), 프리뷰를 길게 누르면 원본(라이브 전/후), 전면 카메라 전환 시 인물 모드 켜기 한 번 제안(기억). 앨범 슬라이더 패널은 "기본/인물" 세그먼트, 인물 탭 상단에 강도 칩, 얼굴 자동 확대 토글.

참조: YUCIHighPassSkinSmoothing(MIT, Core Image 구현), GPUPixel(얼굴 축소 셰이더 알고리즘만 참조해 Metal로 재작성).

### 3.4 저장 방식과 메타데이터 보존 (핵심 요구)
모든 결과는 **시스템 사진 보관함**으로 간다. 앱 안에 사진을 쌓지 않는다. 위치·날짜·카메라 정보는 아래 방식으로 유지한다.

| 경로 | 저장 방법 | 메타데이터 |
|---|---|---|
| **앨범 사진 보정** | PhotoKit **비파괴 편집**(`PHContentEditingInput/Output` + `PHAdjustmentData`). 같은 에셋에 보정본이 렌더링되고 원본은 사진 앱의 "되돌리기"로 복원 | 에셋이 그대로이므로 **촬영일·위치·EXIF 전부 자동 유지**. 앱은 렌더 출력 JPEG/HEIF에도 원본 `CGImageSource` 속성(EXIF·GPS·TIFF)을 `CGImageDestination`으로 복사해 넣는다 |
| **앨범 사진 보정 — 사본으로 저장(옵션)** | 새 에셋 생성(`PHAssetCreationRequest`) | 원본의 EXIF·GPS·TIFF 딕셔너리를 복사하고, `creationDate`·`location`을 원본 에셋 값으로 명시 설정 |
| **라이브 촬영** | `AVCapturePhoto.fileDataRepresentation()`에 담긴 카메라 메타데이터(EXIF, 렌즈, 노출) + 촬영 시각 그대로 저장. GPS는 Core Location으로 받아 `AVCapturePhotoSettings.metadata`의 `kCGImagePropertyGPSDictionary`에 넣어 촬영 시점에 기록 | 원본 에셋에 모두 포함. 보정본은 같은 에셋의 비파괴 편집으로 얹음 → 사진 앱에서 원본/보정본 전환 가능 |
| **쇼츠 내보내기** | `AVAssetExportSession` 출력에 `AVMetadataItem`(creationDate, location)을 첫 클립 값으로 기록 후 사진 앱 저장 | 영상도 촬영일·위치 표시됨 |

- 저장 포맷: 촬영은 HEIF(기본, 용량 절반) 또는 JPEG 선택. 보정 렌더 출력은 원본과 같은 포맷.
- ProRAW로 촬영한 경우 원본 DNG 유지, 보정본은 HEIF로 같은 에셋에 얹음.
- 사진 앱의 "편집됨" 표시가 뜨며, 다른 앱(Lightroom 등)에서 열어도 메타데이터가 보인다.
- 위치 권한은 "앱 사용 중"만 요청. 거부해도 나머지 기능은 동작(위치만 비어 있음).

### 3.5 효과 (릴리즈 2)
- 촬영 탭 셔터 오른쪽 **[효과]** 버튼 → 셔터 위에 낮은 **가로 스크롤 띠**(분류 버튼 스티커·얼굴·렌즈·스타일 + 타일 한 줄)가 열린다. 프리뷰를 가리지 않아 넘겨 보며 바로 확인. 템플릿 **60종**. 촬영하면 같은 효과가 저장본에 들어간다(보정 파이프라인 8단계, `PresetParams.effect`, 사진 앱에서 되돌리기 가능).
- **스티커 = SceneKit 3D 모델**(`Effects/Sticker3D`): 기본 도형·압출 도형 + 물리 기반 재질(금·유광·털 결 텍스처·유리·새틴·펠트), 환경광 반사. 보이지 않는 머리 타원체로 안경다리·머리띠·화관 뒤쪽을 가린다. 고개 좌우 5단계(−30°~30°)를 미리 렌더해 캐시, 얼굴 밝기에 맞춘 톤 + 부드러운 그림자로 합성. 외부 그림 파일 없음(이전 Fluent Emoji PNG는 "PPT 느낌" 피드백으로 폐기).
- 목록(시중 앱 조사 기반):
  - 스티커 16: 강아지·고양이·토끼·곰돌이·생쥐(귀+코/수염), 꽃왕관, 왕관, 하트뿅뿅, 선글라스, 안경, 리본, 신사모자, 학사모, 나비, 천사링, 악마뿔
  - 얼굴 6: 왕눈이, 큰입, 얼굴교환(2명 맞바꿈, 3명 이상 돌아가며), 풍선얼굴, 꼬마얼굴, 외계인
  - 렌즈 22: 볼록, 오목, 소용돌이, 좌우거울, 어안렌즈, 빛터널, 상하거울, 만화경, 유리링, 블랙홀, 늘이기, 회오리, 물결, 일렁임, 수정구슬, 원통, 스플래시, 무한반복, 삼각만화경, 8방거울, 4분할거울, 돋보기
  - 스타일 16: 만화, 열화상, 배경바꾸기, 팝아트, 컬러포인트, 눈내림, X레이, 스케치, 네온, 빈티지, 느와르, 모자이크, 점묘화, 하프톤, 크리스탈, 글리치
- **여러 명**: 스티커·얼굴 효과는 화면의 모든 얼굴(최대 8명)에 적용. 효과용 얼굴 검출은 인물 보정(짧은 변 12% 이상)보다 작은 얼굴(3.5%)까지 잡는다.
- 얼굴 기준점: Vision 랜드마크 → 두 눈 중심·눈 사이 거리(크기 단위)·기울기·고개 좌우(yaw)·코끝·입 중심·입 벌림.
- 효과는 보정 선택(원본/인물/배경)과 독립. 앱 실행 동안만 유지.

## 4. 기능 ② 여행 쇼츠

### 4.1 흐름
```
규격 선택 → (템플릿 선택) → 촬영 보조 → 클립 목록 → 음악 붙여 조립 → 사진 앱에 저장
```

### 4.2 규격 (앱 내 테이블, 수정 가능)
| 규격 | 해상도 | 세이프존 |
|---|---|---|
| **세로 9:16 (기본)** | 1080×1920 | 상단 15%, 하단 20%, 우측 15% (Reels·Shorts·TikTok 공통 회피 영역) |
| 세로 4:5 | 1080×1350 | 없음 |
| 정사각 1:1 | 1080×1080 | 없음 |
| 가로 16:9 | 1920×1080 | 없음 |

촬영은 항상 **세로 4K 30fps SDR HEVC**로 저장하고 내보낼 때 규격에 맞춰 크롭. 한 번 찍은 것으로 어떤 규격이든 출력.

### 4.3 템플릿 (기본 3개 + 직접 편집)
| 이름 | 길이 | 샷 구성 |
|---|---|---|
| 짧게 | 15s | 오프닝 3s → 장면 4s × 2 → 엔딩 4s |
| 기본 | 30s | 오프닝 3s → 장면 4s × 5 → 음식/디테일 4s → 엔딩 3s |
| 자유 | – | 규격만 정하고 샷 제한 없음 |

샷마다 이름·목표 길이만 있다. 템플릿 편집은 샷 추가/삭제/길이 조정뿐.

### 4.4 촬영 보조 화면
- 선택 규격의 프레임만 밝게, 바깥은 어둡게. 세이프존은 반투명 표시.
- 현재 샷 이름 + 목표 길이 카운트다운. 초과하면 진동.
- 3분할 그리드, 수평계(기울면 빨강), 탭 포커스, 노출 슬라이더.
- 안정화 `.cinematicExtended`(미지원 시 `.cinematic`).
- 선택한 사진 프리셋을 프리뷰에 적용(저장은 원본, 조립 때 적용).
- 샷 촬영 완료 체크, 재촬영, 앨범 클립으로 대체.
- 배터리·저장공간·열 상태 경고.

### 4.5 조립 (최소 편집)
- 클립: 템플릿 길이대로 자동 트림(앞뒤 수동 조정), 순서 바꾸기, 무음.
- 전환: 컷 / 디졸브 0.3s 중 택일.
- 텍스트: 오프닝 제목 1개 (여행명·날짜 자동 채움).
- 음악: 음원 라이브러리에서 선택, 시작 지점 조정, 끝 페이드아웃.
- 내보내기: 선택 규격으로 HEVC 렌더 → 사진 앱 저장.

### 4.6 음원 라이브러리 (YouTube 링크에서 앱이 직접 가져오기)
| 항목 | 내용 |
|---|---|
| 방법 | 앱에 YouTube 링크 붙여넣기(또는 YouTube 앱 공유 시트 → TripShot) → **YouTubeKit**이 오디오 스트림 URL 추출 → m4a 다운로드 → 앱 내 저장 → 제목·길이 표시 |
| 위험 | YouTube가 내부 구조를 바꾸면 추출이 깨질 수 있음. YouTubeKit 업데이트 후 재빌드로 해결(과거 이력상 수 주 내 패치됨). 그동안은 파일 앱에서 음원 가져오기가 대체 경로 |
| 하지 않는 것 | 앱 안 YouTube 검색·재생, 업로드. 결과물은 어디에도 올리지 않는 개인용이므로 저작권 이슈 없음 |
| 파일 | 앱 내부 `Music/` 폴더. 삭제·이름 변경 가능 |

## 8. 실행 계획 — 릴리즈 3개, 단계별 진행

### 8.1 원칙
- **릴리즈 1 = 카메라(사진) 모드**, **릴리즈 2 = 효과(얼굴 스티커·렌즈)**, **릴리즈 3 = 동영상(쇼츠) 모드**(09-26 사용자 결정으로 효과를 동영상 앞에 끼움). 앞 릴리즈가 iPhone에서 실사용 가능해진 뒤 다음을 시작한다.
- **한 단계 = 한 세션 분량 = 작성 + 리뷰 한 세트.** 이 클라우드 세션(Fable)이 단계를 지휘한다. 코드 작성은 **Opus 5.5 서브에이전트**에 맡기고, 결과를 Fable이 체크리스트로 리뷰·수정한 뒤 커밋한다. 모델 전환은 없다. 절차는 §11.
- 각 단계는 내용·완료 기준·리뷰 포인트가 정해져 있고, 끝나면 반드시 커밋·푸시 + `docs/HANDOFF.md` 갱신. 토큰이 소진되면 다음 주에 새 세션이 HANDOFF의 "다음 시작 지점"에서 이어간다.
- 이 환경에서는 컴파일이 안 되므로 단계 산출물은 "작성·리뷰 완료"이고, 표시된 **빌드 체크포인트**에서 Mac 세션이 검증한다. Mac 세션도 코드를 고칠 수 있다(§11.1).

## 11. 협업 방식 (클라우드 세션 = 지휘·작성·리뷰 · Mac 세션 = 빌드 위주)

### 11.1 역할
| 세션 | 하는 일 |
|---|---|
| **클라우드 세션 (Fable, 이 세션)** | 단계를 지휘한다. ① 단계 정의(§8)와 HANDOFF를 읽고 **Opus 5.5 서브에이전트**에 작성 작업을 위임(코드+테스트) ② 결과를 `docs/REVIEW_CHECKLIST.md`로 리뷰해 `docs/REVIEW_LOG.md`에 기록, 지적 사항은 직접 고치거나 서브에이전트에 재위임 ③ 커밋·푸시, HANDOFF 갱신. 필요하면 리뷰도 별도 서브에이전트(Fable)에 맡겨 새 눈으로 본다 |
| **Mac 세션** | 빌드 체크포인트에서 `scripts/build.sh`·`test.sh`·`install-device.sh`, `docs/BUILD_LOG.md` 기록, 실기기 관찰. **컴파일 오류·명백한 버그·실기기에서 확인된 튜닝 값은 직접 고쳐 커밋해도 된다.** 설계(§3·§4)를 바꾸는 수정만 HANDOFF "논의 필요"에 적고 클라우드 세션과 맞춘다 |

두 세션 모두 작업 전 `git pull --rebase`, 작업 후 즉시 push. 같은 파일을 동시에 고치지 않도록 HANDOFF "진행 중"을 먼저 본다.

### 11.2 단계 진행 절차 (토큰 소진·주 단위 재개 대응)
```
① 클라우드: HANDOFF "다음 시작 지점" 읽기 → HANDOFF "진행 중"에 기록
② 클라우드: Opus 5.5 서브에이전트에 작성 위임 (단계 정의·리뷰 포인트·코드 규칙 전달) → wip 커밋
③ 클라우드(Fable): REVIEW_CHECKLIST로 리뷰 → REVIEW_LOG 기록 → 수정(직접 또는 재위임)
④ 클라우드: 커밋 `feat(R1-S1): …` 푸시 → HANDOFF "단계 상태"=작성·리뷰 완료, "다음 시작 지점"=다음 단계
⑤ 빌드 체크포인트면 Mac: 빌드·설치 → BUILD_LOG (오류는 Mac이 고치거나 클라우드가 다음 턴에 고침)
⑥ 다음 단계 ①
```
- 토큰 소진 시 마지막 커밋이 재개 지점. 다음 세션은 `git log -5`와 HANDOFF만 보고 이어간다. 작성 중/리뷰 중 어디서 끊겼는지 HANDOFF "진행 중"에 3줄로 남긴다.
- 새 세션 첫 지시 예: "CLAUDE.md와 docs/HANDOFF.md를 읽고 '다음 시작 지점'을 이어서 진행해."

### 11.3 리뷰 체크리스트 (`docs/REVIEW_CHECKLIST.md`)
필수(하나라도 어기면 수정 후 커밋): 사진 보관함 저장·메타데이터 보존 원칙 / 외부 패키지 추가 없음 / 세션 큐·메인 큐 분리 / 원본 손상 경로 없음 / 권한 거부 시 크래시 없음.
품질: 단계 완료 기준 충족 / 테스트 존재·의미 / 큰 이미지 메모리 / 오류 처리 / 한국어 문자열 / 설계(§3·§4)와 일치 / 존재하지 않는 API 의심.

### 11.4 연결 파일
`CLAUDE.md`(규약), `docs/HANDOFF.md`(상태·다음 시작 지점), `docs/REVIEW_LOG.md`(리뷰 결과), `docs/BUILD_LOG.md`(빌드 결과), `docs/MAC_SETUP.md`(Mac 환경), `scripts/*.sh`(Mac 명령), `.claude/settings.json`(권한).
