# 코드 리뷰 체크리스트 (서브에이전트 작성 직후, Fable이 수행)

리뷰 대상: 서브에이전트가 방금 작성한 단계의 변경분(`git status`/`git diff`, wip 커밋 포함).
결과는 `docs/REVIEW_LOG.md`에 기록. 필수 항목 위반은 **수정 필요**, 그 외는 통과 + 권고.

## 필수 (하나라도 어기면 수정 필요)
- [ ] **사진 결과는 사진 보관함으로**, 앱 내부에 사진을 쌓지 않음 (PLAN §3.4)
- [ ] **EXIF·GPS·날짜 보존**: 비파괴 편집 또는 메타데이터 복사 경로를 거침. 새 에셋을 만들 때 creationDate·location 설정
- [ ] **원본 손상 경로 없음**: 실패 시 원본 에셋·파일이 그대로
- [ ] **외부 패키지 추가 없음** (YouTubeKit 외). `project.yml`의 packages 변경 여부 확인
- [ ] **큐 분리**: AVCaptureSession 조작은 세션 큐, UI 갱신은 메인. `@Published`는 메인에서만 변경
- [ ] **권한 거부 시 크래시 없음**: 카메라·사진·위치 거부 경로가 처리됨
- [ ] **설계 일치**: PLAN §3·§4의 파이프라인 순서·동작과 다르지 않음. 다르면 HANDOFF "논의 필요"에 근거가 있어야 함

## 품질
- [ ] 단계 완료 기준(PLAN §8 표) 충족
- [ ] 테스트가 있고 의미 있음(파서·직렬화·순수 계산·빌더). 테스트 없는 순수 로직이 있으면 지적
- [ ] 큰 이미지: 프리뷰는 다운샘플, 풀해상도는 한 번에 한 장, `autoreleasepool`/`CIContext` 재사용
- [ ] 오류 처리: `try?`로 삼킨 실패 중 사용자에게 알려야 하는 것이 없는지
- [ ] Swift 5 모드에서 컴파일될 법한지(존재하지 않는 API, 잘못된 시그니처, 누락 import) — 컴파일 불가 환경이므로 특히 API 이름을 의심
- [ ] 한국어 UI 문자열, 주석 한국어
- [ ] 파일이 모듈 폴더에 있음, 불필요한 파일 없음, `.gitkeep` 정리

```
- (파일:줄) 내용 → 요구 조치
### 권고
- (파일:줄) 내용
### 직접 수정한 것
- fix(R1-S1): … (커밋 hash)
```
